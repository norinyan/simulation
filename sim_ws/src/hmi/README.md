# 仿真控制台

独立 Qt 面板，Gazebo 在另一个窗口显示。分别管理 sim_bringup 场景、control 机器人和 planning 导航进程，不实现规划算法。已知 F2-ROOM→F2-EAST 动态等待超时仍待修复，包迁移不代表该问题已解决。

轮式算法现在可选择 `teb / scan`，首次加载仍默认 `teb`。`scan` 为 SCAN-Planner 的轮式适配版，使用相同运动限制和执行器；足式继续选择 `footstep`。TEB 和 SCAN 均已完成 F1-STAIR→F1-ROOM、F1-STAIR→F2-STAIR 的实际到达与停稳验证，详情见项目 README；这不表示所有点对或既有动态等待问题已解决。

容器内构建并启动：

```bash
source /opt/ros/humble/setup.bash
cd /workspace/sim_ws
colcon build --packages-up-to hmi --cmake-args -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
source install/setup.bash
ros2 run hmi panel
```

默认专用 ROS_DOMAIN_ID=91、Gazebo master=http://127.0.0.1:11355，避免接入已有命令行会话。更换参数：

```bash
ros2 run hmi panel --domain-id 92 --master-uri http://127.0.0.1:11356
```

另开终端查询面板 Topic 时先 export ROS_DOMAIN_ID=91。只支持本机容器内 Gazebo。

使用顺序：

1. 选场景与速度，启动仿真，等待模型列表和实际时钟就绪。
2. 选出生点与目标点，生成机器人，等待实际 odom 和执行器状态。绿色圈表示出生点，红色圈表示目标点。
3. 两级台阶选择 A→B、正常速度；三层楼选择任意两个不同预设点。从后端提供的列表独立选择全局／轮式／足式算法，点击“开始任务”自动规划与执行；计算状态及耗时可见。
4. “停止任务”取消计算或执行并停车，保留实际安全姿态，不自动收腿或续跑。DONE后可从实际终点开始下一任务；实际起点／轮式状态不匹配时明确拒绝，必要时移除重生。“关闭仿真”关闭整个会话。
5. 选择总览、俯视、内部透视、三层同屏，或点击第三人称跟随；“恢复所选视角”退出跟随。跟随采用后方 4.8 m、抬高 4.8 m 的宽视野（水平视场角 80°）；墙、门、窗仅在显示中淡化，避免房间墙体遮挡，退出跟随后恢复原材质透明度。

预设点集中在 sim_bringup/config/scene.yaml 的 presets：两级台阶 A/E/X/B，三层楼点位为：F1 大门内侧、楼梯口前、右上房间；F2 楼梯口前、右下房间、走廊最右端；F3 楼梯口前、走廊最右端、中间下方窗前。两场景共 13 个点。大门外没有楼板支撑，因此入口点放在门内约 0.6 m 的安全区。坐标为地面 x,y,z,yaw，机器人生成自动加轮式高度。三层放置启用真实几何碰撞和地面支撑检查；静态预检不保证动态行人不会与停放的机器人相遇，实际碰撞仍由执行器保护。

三层闭环可选正常或 5 倍目标倍率，10 倍仅用于场景观察；原两级台阶闭环保持正常速度。

路径在 GUI 内使用线条绘制，避免反复更新网格阻塞渲染。机器人、行人和跟随相机采用约 100 ms 的显示缓冲插值；该延迟仅影响画面，规划反馈、控制和碰撞使用实际状态。截图仅在请求时读取一次，不持续读取每帧。

两级台阶保留 A→E→X→B；三层9个点开放72个有向组合。完整三维全局路线决定轮足模式，楼梯与中间平台全程足式，楼梯出口停稳后收腿。改变同层／跨层类型不要求重生；执行前仍检查实际轮式起点和停止状态。场景地图由场景端初始化并持久发布，规划晚启动可收到，换任务不重新解析。出生配置只在生成机器人时写入；起终点及算法通过任务服务提交，同进程可更换任务。行人阻挡时显示 `WAIT_OBSTACLE`，条件允许后恢复；等待超时、反馈失效或执行器保护明确失败。

三层行人均从左下房间 `(-4, -4.45)` 到右下房间 `(4, -4.45)` 水平直线往返，端点各停顿 8 s，速度和启动延迟在 World 的三个行人插件中配置。机器人须在横穿前等待，恢复前检查实时障碍；行人不主动让行。

二层右下房间点位 F2-ROOM 的 y 从 -3.50 调整到 -3.65 m，保留房间内点位用途，为双向进出留出转向净空。任意点选和电梯控制未开发。

状态来自 ROS 实际反馈；按钮点击成功不等于任务完成。运行配置、进程日志和规划数据在 `${XDG_STATE_HOME:-~/.local/state}/hmi/<时间>/`。面板只管理自己创建的进程组，不按进程名停止其他仿真；退出面板时异步等待 SIGINT→SIGTERM→SIGKILL 清理完成。

模块：app.py（界面与状态）、coordinator.py（按任务ID协调提交、规划与执行）、session.py（进程生命周期）、ros_bridge.py（ROS反馈／服务）、presets.py（点位与静态预检）。`/planning/set_task` 接收起终点与算法；`/planning/algorithms` 返回可选算法；plan 服务响应仅表示接受，coordinator 等同任务ID的 PLAN_READY 后再请求 execute。停止统一走后端服务，旧任务迟到事件不触发执行。

导航接口：后端通过统一规划接口调用算法；算法默认值和公共约束分别在 `planning/config/planning.yaml` 的 `planners`、`motion` 中配置。通过SetTask服务同时提交起终点和三类算法，任务中固定；场景／运动约束更改需要重启。规划期间“停止任务”可取消请求，晚到的结果不会重新启用执行。三层任务通过同一规划接口运行；新增左右髋部偏航关节支持平台转向，按理想轨迹进行运动学执行，不包含动力学平衡控制。跨层计算预算使用 `planners.stair_timeout`，执行预算按轨迹时长计算。

足式每步按现有机身、摆腿及关节速度／加速度限位生成步时，非固定4.5秒；无额外全段二次缩放。落脚点显示实际采用的完整足式段，行走与视角切换时保留，新版本替换，开始新任务或移除机器人时清理；实体碰撞不参与显示更新。

仅保留简要任务结果；高频轨迹CSV导出及其参数已删除，可视化输出保留。GUI截图和视角人工确认不作为验收要求。
