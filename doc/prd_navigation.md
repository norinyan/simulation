# 轮足机器人导航打通 PRD

日期：2026-10-21。状态：阶段一、二已完成验收；阶段三未开始，等待确认。

## 1. 目标与范围

将 HMI、场景几何、规划算法和机器人执行接成闭环。分三个阶段实施，每阶段验收后再进入下一阶段。

最终目标：现有九个三层楼预设点之间的同层与跨层任务，包括上下楼、轮足切换、基本行人阻挡处理及实际状态显示。既定任务不可达属于验收未通过；正确停止和说明原因不能替代任务成功，也不能借此缩减目标。

本轮不做：电梯、任意点选目标、SLAM、传感器定位、动力学平衡、复杂人群预测、楼梯绕人、新 HMI 框架、算法插件系统或批量评测平台。不为证明接口可替换而额外实现第二套算法。

**待确认边界：平台允许切轮式转向。** 现有腿部为平面关节机构，本轮不承诺全程足式转身。此策略须在阶段三开始前确认，不通过直接旋转模型、改楼梯或改机器人机构绕过。

**实施前可行性核对：** 重构前，仅核对现有楼梯净宽、步高与踏面、平台转向和轮足切换空间、上下楼所需关节范围及净空。发现硬性不满足时先报告，不能投入两阶段后再发现跨层目标不可实现。此核对不代替阶段三的实际通行验收，不增加阶段。

本轮只验收运动学轨迹、碰撞和几何支撑，不将模型完成动作等同于真实机器人动力学可行。

## 2. 架构与统一接口

```text
World + 机器人几何 + 场景配置
                ↓
        场景几何与楼层连接
                ↓
HMI 起终点 → 任务调度 → 当前路段
                         ├─ 轮式：全局路径 → 局部轨迹
                         └─ 足式：落脚点与身体轨迹
                                      ↓
                          机器人执行器 → 实际反馈
                                      └→ 推进任务或停止
```

允许重构现有接口和代码，不以保留内部结构为目标。职责如下：

| 模块 | 职责 |
|---|---|
| `simulation_hmi` | 选择任务、发送请求、显示实际状态，不处理算法细节 |
| 场景适配 | 从 World 碰撞体获得障碍、地面支撑和楼层连接，不重复抄家具坐标 |
| `planning_node` | 接收任务、选择算法、组织路段、统一校验、闭环执行与记录 |
| `planning` | 与 ROS/Gazebo 无关的算法输入输出，不读取 World、不操作机器人 |
| `robot_executor` | 执行指令、反馈状态、保留碰撞及支撑保护 |

### 算法契约

在现有 `global_planner.h`、`local_planner.h` 中重构，保留三种职责，避免强行合成一个接口：

| 类型 | 统一输入 | 统一输出 |
|---|---|---|
| 全局规划 | 当前平地段起终点、公共场景几何、机器人轮廓及安全距离 | 带位置与朝向的路径、成功状态及失败原因 |
| 轮式局部规划 | 全局参考路径、实际位姿与速度、当前障碍、公共运动约束 | 带时间的轨迹、成功状态及失败原因 |
| 足式局部规划 | 楼梯段起终点、地形、机器人几何及运动约束 | 足步和身体轨迹、成功状态及失败原因 |

- 米、弧度，统一坐标系；规划位姿为地面投影，身体高度由执行适配转换。明确轨迹时间、速度和加速度字段的含义。
- 公共几何必须表达地面支撑或禁行区域，不能让算法将楼梯洞当成平地。
- 以实际加载的 World 和展开后的机器人模型为准，检查规划配置与其一致；完整处理所用碰撞体的位姿与朝向。不支持的碰撞几何明确报错，不得静默漏掉。
- 公共速度、加速度、安全距离和到达条件由任务配置提供；TEB 的迭代次数、离散间距和重试逻辑留在算法内部。
- 算法创建与参数装配处允许引用具体实现；运行和控制流程通过抽象接口调用，不依赖 TEB 特有字段，不按算法类型编写控制分支。诊断字段只用于日志。
- 在 `planning.yaml`／ROS 参数选择算法，默认 A*、TEB、现有足步算法。未知名称明确报错，不静默回退。暂不增加 HMI 算法菜单。
- 新增算法只需增加实现、注册和构建项；无需修改 HMI、场景适配或机器人执行器。
- 跨层连接和轮足分段归任务调度；全局算法本轮负责平地段，不要求每个算法理解整栋楼的轮足动作。
- HMI 通过运行时任务快照传递场景和起终点，沿用现有规划／执行／停止服务。规划绑定起终点、算法和配置；任一项变化后旧规划失效，执行期间禁止修改任务。
- 算法结果在执行前统一校验碰撞、支撑、运动约束及时间有效性；不以算法自报成功作为可执行依据。动态障碍状态过期时停车，不继续执行旧轨迹。
- 算法计算设置耗时预算，不得阻塞停止和反馈处理；超时或取消后的结果作废，不得恢复发指令。保留执行器独立超时保护。
- 取消采用协作式检查，新增算法须在搜索循环或求解器中响应预算；本轮不引入进程隔离。算法及约束在进程启动时固定，运行中修改参数明确拒绝。

### 兼容与公平比较

- 保留现有启动入口、参数语义、两级台阶 A→E→X→B 任务，以及现有 ROS 规划服务和机器人指令接口。
- 内部 C++ 接口和 YAML 结构允许调整，所有调用方与测试同步迁移；不维护两套内部实现或旧 YAML 兼容解析器。
- 两场景配置集中在现有 `scene.yaml`，算法配置集中在 `planning.yaml`，面板点位集中在 `presets.yaml`；不增加平行配置文件。
- 原任务的到达标准、碰撞和安全限制不放宽；旧 CSV 格式保持不变，新任务结果单独记录在运行目录。
- 比较算法时固定场景、起终点、机器人几何、公共约束和仿真倍率。记录算法名称与参数、规划耗时、实际用时、实际路程、终点误差及失败原因。
- 算法内部优化代价不作为跨算法通用评分。动态场景比较须复位行人初始相位，不用不同时间的障碍快照直接比较。

## 4. 阶段二：三层楼同层导航

**结果：** HMI 选择同层预设起终点后，机器人能够规划、行驶、到达并停车。

工作：提取实际碰撞几何，正确处理坐标变换、机器人占据高度、地面缺口和楼层筛选；接入所选任务与实际反馈。三层行人统一改为左下房间与右下房间之间的水平直线往返，保留真实碰撞，增加实时障碍更新及受阻停车、条件允许后重规划。

动态处理以直线往返行人横穿机器人路线为范围：两端为房间内点位 `(-4, -4.45, 楼层高度)` 与 `(4, -4.45, 楼层高度)`，端点各停顿 8 s；保留各层速度与启动延迟。穿过现有门洞，不改变墙体、家具或机器人任务。行人持续往返，不因遇到机器人返程或消失。

机器人提前预测交叉冲突；临近共享路段时，检查现有路径通过整个共享段的预计时序，在行人路线之外刹停，通道清空后继续。二层门洞存在短暂共用，端点停顿设为 8 s 以提供通行窗口；该参数固定用于本阶段验收与后续算法对比。局部规划可绕行；本阶段不增加通道预约、自动寻找退让区或复杂倒车，不承诺任意行人运动下都能通行；足式动态绕障不在本阶段内。

阻挡等待为非终止状态，障碍离开后须重新校验或规划才能继续；用户“停止运动”仍终止任务。局部无法通过时允许全局重规划，等待超时则明确失败。保护触发或机器人停车后被行人撞到，均不计为避障成功。

验收：

1. 三层各一条代表路线：一层门口→右上房间；二层楼梯口→右下房间；三层楼梯口→下方窗前。实际穿过通道、转弯并停在目标处。
2. 其余预设点完成姿态及连通性检查；同层各点对完成离线规划检查，不反复实跑全部排列。不可达情况必须解决或列明阻碍，不能悄悄删除点位。
3. 新任务终点位置误差≤5 cm、朝向误差≤5°；仅规划、执行、停止和失败提示均按实际反馈工作。
4. 一个行人横穿案例，实际完成无碰撞通行及必要的等待后继续；同时检查“等待”和“用户停止”状态不同。不得关闭行人或碰撞来通过验收。

## 5. 阶段三：上下楼与跨层任务

**进入条件：** 前两阶段通过；平台转向策略已确认，平台空间检查可行。

**结果：** 选择跨层预设起终点后，自动完成平地、楼梯和平台动作，最终到达并停车。

工作：适配实际楼梯朝向和下楼轨迹；在现有 `planning_node.cpp` 中组织轮式段、足式段和切换动作。安全切换须确认位置、朝向、停稳和支撑，并等待模式完成反馈。连续直行足式段保持足式；平台按已确认策略换向。

跨层任务的阶段／总超时按路线长度、速度及足步时长配置，不沿用两级台阶的固定预算。不得靠缩短动作、提高限制或忽略超时来通过验收。

验收按顺序进行，局部动作未通过时不启动整程：

1. F1↔F2、F2↔F3 楼梯连接均能双向通行，足步落点、身体轨迹及轮足切换通过碰撞与支撑检查。
2. 完成一条 F1→F3 任务及其反向任务；模式和路段状态来自实际反馈。
3. 阻挡、切换失败或反馈超时能够停止并说明原因。行人占用楼梯时保守拒绝进入，不做楼梯绕人。
4. 最终回归一条同层任务和原两级台阶任务；原标准不变。

## 6. 交付与停止条件

- 每阶段交付：代码、必要配置、使用说明、简短验收结果；验收记录包含任务、参数、实际结果和日志位置。阶段通过后停止，等待确认再进入下一阶段。
- 复用现有观察视角展示路径和运动，不制作额外可视化工具；不覆盖既有图片或验收证据。
- 优先加速检查；实跑提高至 5/10 倍前确认闭环和反馈正常。倍率导致异常时记录原因并使用可稳定运行的倍率，不降低约束换取通过。
- 除受影响功能、代表案例和规定回归外，不重复跑全量任务。日志和临时配置放运行目录，不提交构建产物。
- 预计新增：业务文件 2 个、必要足步测试 1 个、本文 1 个。其余修改现有文件；不计划删除现有文件、增加包或增加 launch。

后续若因实际问题确需新增模块、改变平台策略、修改机器人机构或扩大动态避障范围，先列明原因和影响，再决定是否纳入。
