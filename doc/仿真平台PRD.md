# D1–D5.1 阶段记录

本部分保留已实施阶段的职责、接口和关键决策，替代原详细实施方案；后续阶段已替代的规则仅作为历史记录，不再作为当前要求。

## D1：全局规划节点

- `global_node.cpp` 负责读取配置、选择算法、加载离线地图、确定起终点、调用规划及统一发布；`global_node.h` 定义算法请求、结果和接口，算法实现放各自目录。
- `global_cfg.yaml` 集中配置九个点位、起终点、预设/odom 起点来源、算法、地图、约束和超时。地图预处理离线执行，节点每次任务重新搜索。
- 输入：`/global_planning/goal`（String 预设目标名）、`/global_node/replan`（Trigger）、`/robot/odom`；输出：`/global_path`（GlobalPath）。重规划保留目标，以实际位置为起点；忙时拒绝新请求，不排队。
- 输出统一为 `world` 地面路径，楼梯及中间平台标记 `foot`；检查端点、数值、模式及超时。失败发布空路径并报告原因，清空路径不等于停车。

## D2：局部规划节点

- `local_node.cpp` 负责全局路径与 odom 接收、局部段选择、算法调用、轨迹校验和发布；`local_node.h` 定义共用请求、结果和算法接口。
- 参数集中在 `local_cfg.yaml`。输入 `/global_path`、`/robot/odom`，输出 `/local_trajectory`（LocalTrajectory）；算法专用逻辑放各自目录。
- 全局路径为地面高度，局部轨迹为 `world` 下的本体 XYZ/yaw；必须检查起点衔接、严格递增时间及运动约束，无效结果不发布。
- 历史规则为每条全局路径只生成一次局部段；后由 D4.2 接通连续执行，再由 D5.1 改为滚动规划。规划或发布成功不代表执行完成。

## D3：PCT 全局算法迁移

- 实现集中在 `global_planning/pct/`：地图生成、缓存读取、搜索、可选优化及适配；参数放 `global_cfg.yaml`，不搬旧导航节点或预定义楼梯路线替换逻辑。
- 离线从 World 碰撞几何生成多层缓存及楼梯/平台区域信息；运行时加载 PCTMAP02，匹配支撑面和高度切片，单次搜索后校验，不使用其他算法兜底。
- `/global_path` 保留真实地面搜索路线；楼梯及平台模式依据区域信息。优化代码已迁入、默认关闭，机身优化参考不能冒充地面路径。
- 原验收范围为同层、相邻楼层、跨两层及代表反向路线的路径正确性、不可达/损坏地图/超时处理；不等于局部规划或完整执行验收。

## D5：真实数据 HMI

- React + Three.js 前端，FastAPI + rclpy 后端；HTTP 提交操作，WebSocket `/ws` 推送真实消息。场景取实际 World，机器人由 odom 驱动，不使用预制动画或 Gazebo 视频嵌入。
- 操作顺序：选择点位/算法 → 启动仿真 → 开始全局规划（机器人不动）→ 启动任务；仅已接入的 PCT/SCAN 可用。离线的是地图预处理，本次路径仍实时搜索。
- 后端接口：`/api/simulation/start|stop|pause|resume`、`/api/planning/global`、`/api/task/start`；只管理本次启动的进程，不终止外部仿真，临时配置不覆盖源配置。
- 局部节点提供 `auto_execute`（独立运行默认 true，HMI 设 false）及 `/local_node/start_task`（Trigger）。全局/局部通过 `/global_planning/status`、`/local_planning/status` 发布 String JSON 状态和原因。
- 刷新或重连只恢复展示，不重复任务；配置变化后旧路径失效，须重新规划。完成以最终 odom 到位且静止为准，服务受理不代表成功。

## D5.1：滚动规划、桌面窗口与资源测评

- `local_node` 异步滚动规划，同时最多一次；从预测切换状态传入 p/v/a，并复用已接受轨迹暖启动。默认前视 2 m、周期 0.5 s、预约提前 0.5 s，参数以 `local_cfg.yaml` 为准。
- `LocalTrajectory.header.stamp` 为绝对仿真生效时间，点时间为相对时间；位置、速度、yaw 连续接替，拒绝过期或不连续结果，保留受限停车尾段。执行器用三次 Hermite 插值重建轨迹，不瞬移、跳段或强制清零速度。
- 关键修复：精确固定起始 p/v/a；全轨迹碰撞检查与曲线距离代价；局部坐标下求解；无新增避障方向不空转重启；时间分配后用 Refine；楼梯 XY 与固定 Z 的参考约束；碰撞代价尺度和有界罚项反馈。避障权重经单变量对照由 1 调为 2，未降低安全距离。
- 通用限值：速度 0.8 m/s、加速度 0.8 m/s²、yaw 速度 1 rad/s、点障碍距离 0.05 m；优化期望净空 0.10 m 是软目标，不等于硬验收距离。
- PySide6 + Qt WebEngine 复用 HMI；入口 `ros2 launch sim_bringup hmi.launch.py`。地图概览、全局线、局部真实消息记录、地图/跟随双视角和右侧控制面板；橙线只显示有效局部轨迹未执行部分。
- 按实际全局/局部节点分别采集 CPU、RSS 和单次规划耗时；CPU 单核满载为 100%，内存 MiB、耗时 ms，使用单调时钟。不是能耗测量，也不把 Gazebo/HMI 开销计入算法节点。
- 当时 Gazebo 验收通过 `F1-ENTRY → F3-EAST`：235 条轨迹、234 次运动中接替，最小实际点净空约 7.79 cm，速度/加速度未超限；暂停恢复通过。本阶段提交 `d24dada`。
- 后续 D6 的关闭动态障碍回归再次在三楼楼梯末端失败，原因未定；上述单次通过不等于任意切换时刻稳定，也不代表所有点对或下楼均已验收。遗留问题纳入 D6.1。

# D6：动态障碍与局部避障

目标：Gazebo 中每层增加一个按固定路线往返移动的方盒，共三个；局部规划根据实时观测预测障碍运动，实现绕行、等待和恢复，服务后续真实感知接入。

第一版范围：每层一个方盒，仅在各自楼层走廊运动，固定朝向、路线、速度和启动相位，不随机生成。机器人沿用理想质点，障碍使用完整盒体；本阶段验证动态规划链路，不代表真实机器人尺寸或动力学验证。

## 1. 障碍物与理想感知

- `sim_bringup` 新增障碍运动节点和 `config/dynamic_obstacles.yaml`，配置盒子尺寸、路线端点、速度、启用状态；根据仿真时间驱动 Gazebo 实体，不穿静态墙体。关闭时不生成盒子，暂停时停止运动。
- 每层分别按实际地图布置路线，盒体全程不穿墙、不进入楼梯及狭窄必经口，初始位置不与机器人重叠。有绕行空间时预留安全余量；横穿允许暂时占道，但必须在有限时间内自行离开，且机器人有足够距离停车等待。不得永久封死通路，也不根据机器人位置主动让路。
- 固定路线仅由运动节点持有，不传给局部规划。观测位置、姿态和速度取自 Gazebo 实际实体状态，不直接发布预定运动命令作为观测。
- 只新增一个 `DynamicObstacle.msg`：`std_msgs/Header header`、`string id`、`geometry_msgs/Pose pose`、`geometry_msgs/Vector3 size`、`geometry_msgs/Twist twist`，不增加数组消息。
- 三个盒子共用 `/dynamic_obstacles` 话题，按唯一 ID 分别发布，每个盒子 20 Hz；`frame_id=world`，时间戳为采样仿真时间，速度为世界坐标速度。第一版启用后不在任务中途增删盒子；状态过期不视为障碍消失。动态避障关闭时不等待该话题。
- 这是理想感知输入；不增加雷达、识别或跟踪系统。后续真实感知沿用该输入边界，不依赖障碍物的预设路线。

## 2. 预测与 SCAN

- `local_node` 订阅 `/dynamic_obstacles`，按 ID 保存最新观测、拒绝倒序更新，分别检查时间戳；每次规划复制一份各障碍最新状态组成的快照，传给 SCAN，不让异步更新改变同一次求解的目标函数。只处理预测时域内可能接近执行轨迹的障碍，筛选计入高度、盒体尺寸和预测余量，不能只按楼层标签忽略障碍。
- 第一版采用匀速预测：`p(t)=p_obs+v_obs*(t-t_obs)`，保持观测朝向；不读取往返端点，不提前知道转向。障碍转向后根据新观测更新预测。
- 每个候选轨迹点使用绝对执行时间：`轨迹切换时刻 + time_from_start`；优化、结果验收及在执行轨迹检查使用同一预测和盒体距离规则，不能把动态障碍简单冻结在当前位置。
- 为 SCAN 增加随时间变化的盒体避障代价和最终检查；时间分配变化后重新计算预测碰撞。保留静态 World、地形、速度和加速度约束。
- 最小距离采用既有 `point_clearance`，另加可配置预测余量；余量随预测时间增长，不通过降低原安全距离通过验收。固定速度模型不能保证对任意突然转向或加速安全。
- `local_cfg.yaml` 增加动态避障开关、观测超时、预测时域、预测基础余量及每秒增长量。预测时域至少覆盖本次发布轨迹的停车尾段，不发布超出有效预测范围的执行部分。

## 3. 执行中检查、等待与恢复

- 周期重规划之外，新观测触发当前及已预约轨迹的剩余部分检查；发现预测冲突时优先重规划，包含现在到预约切换时刻的时间段。
- 旧轨迹不安全时，不能仅报告失败后继续执行旧轨迹。需要生成满足运动约束的停车轨迹，并明确替换或撤销已预约轨迹；必要调整 `ideal_control` 的预约管理，不增加真实机器人控制分支。
- 依据当前速度、加速度上限、规划及切换耗时计算停车距离和提前量；对静态和预测动态障碍验证停车全过程。保留同一时刻的位置、速度连续性，不瞬停或瞬移。
- 观测过期或暂时无可行绕行路线时进入等待，能安全停车则停车；障碍离开且观测有效后，从实际 odom 自动恢复。同一时刻最多一次规划，限制重试频率。
- 若已经来不及生成安全绕行或停车轨迹，明确报告安全失败，不能把停车当成必然安全，也不能声称可避免障碍主动撞击。

## 4. HMI 与职责边界

- HMI 增加动态障碍开关，任务启动前配置；双视角按实际状态绘制盒子，显示避让中、等待障碍、观测过期及失败原因。保留已有轨迹和计算资源显示，不新增独立报表系统。
- `sim_bringup` 管实体生成、运动和观测发布；`local_node` 管快照、触发和等待恢复；SCAN 管预测避障；理想执行器管轨迹接替；HMI 管操作展示。
- 允许修改：`src/sim_bringup/` 必要节点、配置、启动及依赖；`src/interfaces/` 新增障碍消息及构建；`src/local_planning/` 动态输入、SCAN 优化/检查及参数；`src/control/src/ideal_control.cpp` 必要的预约替换；`src/hmi/` 对应操作和显示。
- 不改 PCT、静态 World、预设点位、现有路径消息、机器人模型及旧控制器；不增加其他算法、多障碍协同或楼梯动态避障，不修改 README/手册。

实现顺序：障碍运动与实时观测 → 带时间的预测及 SCAN 避障 → 在执行轨迹检查与安全停车/恢复 → HMI 接入 → Gazebo 验收。

验收：

- 先在一层固定路线验证有空间横穿、暂时堵路后离开两种情形，再启用其余楼层；三个盒子按各自配置运动，验证每层均可通过，且不同楼层障碍不会误触发避让。场景布局和速度提前核算可绕行/可停车空间。
- 有空间时产生实际绕行轨迹；无法安全通过时等待，障碍离开后自动到达终点，不永久堵路。固定路线、速度和仿真启动相位，记录实际轨迹，不能只凭规划成功判定通过。
- 独立用 Gazebo 实际位置与盒体计算最小间距和碰撞：当前机器人质点进入盒体即为实际碰撞，不能依赖理想执行器的物理碰撞阻止穿透。实际最小间距须达到原安全距离；核对运动约束、轨迹接替连续性及最终到位静止。记录避让次数、等待时间、规划耗时与 CPU/RSS，复用现有显示。
- 覆盖观测中断、盒子转向后预测更新、暂停恢复；不可安全处理的情形明确失败，不继续已知危险轨迹。
- 动态避障关闭后回归 `F1-ENTRY → F3-EAST`，保留 D5.1 已通过行为；必要验证完成后清理临时产物，不新增常驻测试脚本。

# D6.1：独立单向人流与局部规划评测

目标：保持质点机器人，每层设置一个不同位置的行人生成点，持续生成单向行人，形成独立于机器人任务的人流，用于评测局部避障效果和计算开销。

本节替代 D6 固定三个 ID 及旧 D6.1 的六障碍、接近触发、原路返回规则。行人仍以完整方盒表示，不增加机器人尺寸、关节或真实动力学。

## 1. 生成与运动

- `sim_bringup/config/dynamic_obstacles.yaml` 每层配置一组：生成点 A、终点 B、必要的中间路线点、行人尺寸、速度、途中停留时间、首次生成延迟及再次生成间隔。三层 A/B 布置不同，不提供场景选择。
- 配置提前写好；Gazebo 场景及实体服务就绪后，按仿真时间开始生成。不订阅全局路径或任务状态作为触发条件；未开始规划或任务时，人流也独立运行。
- 本版每层最多一名在场行人：在 A 生成 → 沿固定路线单向走到 B → 删除成功 → 等待配置间隔 → 在 A 生成下一名。不折返、不瞬移、不追逐或主动配合机器人让路。
- 每次生成分配不复用的实例 ID，如 `f1_ped_001`；三层分别计数。A 点实际被机器人或其他实体占用时延迟生成，不能重叠出生；出生安全检查不用于刻意制造相遇。
- A/B 均避开机器人预设点、楼梯、狭窄门口和必经停车位置；B 位于通行路线外。完整盒体全程不穿墙，多个行人同时出现时也不能合起来永久封路。生成间隔必须留下可通行窗口，不以密集连续人流封死通道。
- 三条路线结合地图覆盖横穿、沿通道行走及途中暂时占道；同一条沿通道路线相对机器人方向不同，可形成迎面或同向相遇。不强行要求每次任务遇到全部行为，也不根据机器人实时位置改变行人路线或生成周期。
- 到达 B 后调用 Gazebo 删除服务；删除失败则继续发布停在 B 的实际观测，不报告消失、不生成下一名。暂停时运动、停留和生成计时全部暂停；重新规划或启动新任务不重置人流，停止仿真才清理本次实体及计时。

## 2. 观测与生命周期

- 继续使用单个 `DynamicObstacle.msg` 和 `/dynamic_obstacles`，保留现有字段，新增 `bool active`，不新增数组消息。`frame_id=world`，时间戳使用仿真时间。

# D6.2：动态避障连续执行与停车修复

状态：已实施重试、停车及诊断修复；完整验收未通过，二楼迎面避让仍失败。

## 1. 执行与停车规则

- 新轨迹成功且通过检查后正常接替，绕障成功不要求停车。
- 新轨迹失败时，先检查实际在执行及已预约轨迹：剩余轨迹安全、观测有效且还有处理时间，则继续执行并按既有周期重试；不因单次失败立即停车，不按固定失败次数决定停车。
- 根据当前位置/速度/加速度、经验证的停车轨迹时长、规划与接替耗时确定最晚停车时刻。重试不能耗尽停车余量；旧轨迹的停车末端继续保留，已知危险轨迹不得继续执行。
- 到达最晚停车时刻前仍无可用轨迹，则执行通过静态/动态碰撞及运动检查的停车轨迹；预约切换前的执行部分也必须安全。观测过期沿用故障保护，不按“旧轨迹安全”继续走。
- 停车还要检查停车后等待位置的预测冲突；若行人将经过该位置，应提前用现有 SCAN 求安全绕行或脱离轨迹，不能持续原地重试。预测只在有效时域内使用并随观测更新；确实无安全解时明确失败，不承诺任意相遇都能避开。

## 2. 停车轨迹与求解器
