# 二阶段 PRD

## Dx 任务执行流程

本节已冻结，适用于后续各 Dx；仅在用户明确要求时修改，不随任务实施自行调整。

1. **理解与分工**：主 Agent 读取 Dx，明确目标、边界和验收条件；按任务确定 subagent 数量、职责、交付物和依赖。简单任务直接完成，仅讨论时不实施。
2. **调查与汇总**：各 Agent 调查负责部分，返回现状、建议和风险；主 Agent 汇总证据、解决冲突，从整体链路确定最小必要方案，避免局部最优和提前扩展。
3. **计划与实施**：主 Agent 维护一份计划，可使用 Goal、Plan 工具；统一接口，划定修改文件和验证责任后分配实现，避免同时修改同一文件。子 Agent 完成子任务，主 Agent 协调依赖、处理公共部分并集成结果，不覆盖无关改动。
4. **排错与范围控制**：先提假设，再做最小实验；同因连续失败两次后重新判断，再试须有新依据。成本明显超预期及时说明；需改变主要方案、行为或验收标准时，暂停相关工作，由用户决定。
5. **集成与 Review**：主 Agent 汇总改动，安排非原实现者审查需求、接口、兼容性和多余设计；问题须有定位与证据。分配修复后只复查受影响部分，不无故重复整轮审查。
6. **验证与验收**：各 Agent 提供针对性验证结果，主 Agent 补齐集成验收和必要回归；复用有效证据，不重复未受改动影响的检查。长时间验证先定时限和结束条件，不以编译通过或子 Agent 声明代替验收，不降低标准。
7. **记录与交付**：主 Agent 在 Dx 中记录实际改动、验收证据和遗留问题，简要交付，通过即停止。只新增必要文件，不另建计划、总结或 Review 文档；提交、推送和发布须有用户明确授权。

### 3. 流程

1. **纠正预览**：叠加原始点云、提取地面及障碍；按真实地面加当前本体参考高度（现为 0.44 m）查询净空，结合 PCT 通行结果显示。禁止用“任意 Z 存在空闲”的投影代表可通行区域。
2. **定位碎片**：区分显示错误、地面筛选、稀疏采样、真实障碍与未知边界；给出代表位置和连通区域证据。未经证据不通过扩大连接阈值或填洞追求连通。
3. **改善与展示**：仅修复已确认问题；在 Gazebo 贴合真实地面显示带图例的颜色覆盖，保留墙体与通道，可俯视/倾斜观察，并可切换原场景外观以对照。覆盖只作显示。
4. **较长路线**：在真实连续可通行区域选两个更远点，优先评估 5～10 m 路线；先报告实际间距与路径长度，再写入预设点。必须长于当前点对及约 2.46 m 路线，数据不足则报告，不跨未知区域制造路线。
5. **验证与交付**：完成 PCT、SCAN、Gazebo 端到端验证，再打开 Gazebo 向用户展示整层及代表性局部；技术结果与用户查看结果分别记录。

### 5. 验收

1. **地图展示**：向用户实际打开 Gazebo，展示整层及地面/墙体/通道局部；图例清晰，可俯视、旋转并对照原几何，由用户确认是否便于观察。不能只交一张散点图。
2. **判定可信**：颜色与 PCT/SCAN 对应查询一致；按地面高度判定，区分有效支撑、障碍和未知。颜色不代表整片自动连通，线段净空及路径仍须验证。
3. **功能可用**：六产物一致、安装引用有效；较长点对由 PCT 规划、SCAN 滚动生成轨迹，Gazebo 中机器人到达静止，并满足现有净空、速度、加速度与到达条件。

5. **不降低标准**：原数据不足以完成展示或较长路线时，说明具体缺失与影响，等待用户决定；不以好看、文件生成或局部成功代替验收。
